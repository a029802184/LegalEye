# 法眼 LegalEye V4 驗收

環境為 Windows、Node.js 18、正式建置版與本機 Edge。測試採合成或虛構資料。Chrome 實測的範圍與受管裝置的待確認項目見 [Chrome 可行性](chrome-ocr-feasibility.md)。

型別檢查及正式建置通過。Vitest 92 項通過，包含原有 84 項。Playwright 六種視窗共 50 項通過，10 項略過。略過的是在桌面執行的藍底 OCR 與 11 頁效能樣本，兩項均在桌面通過。完整證號更正納入最後建置後，桌面及手機的逐頁貼入與批次核對共 4 項再驗通過。Edge 測試擷取應用程式產生的下載檔名和 Blob 內容，避免無頭下載開啟的空白分頁干擾後續測試。

## 固定樣本前後比較

在 `legal/` 執行 `node tests/benchmark/v3-address.mjs --v4`。腳本以相同樣本比較 Git 的 V3 `6166d59` 和目前程式，涵蓋緊鄰及斷行姓名標籤、格式等價、兩人同頁、換行地址、掃描疑點與真正差異。

| 指標 | V3 | V4 |
|---|---:|---:|
| 姓名擷取正確 | 3／6 | 6／6 |
| 地址判定符合預期 | 6／8 | 8／8 |
| 地址一致 | 3 | 5 |
| 地址尚未抽出 | 1 | 0 |
| 保留掃描巷號疑點待看原件 | 1 | 1 |
| 抓到真正的門牌／樓層或巷號差異 | 2 | 2 |
| 誤報為地址不一致 | 1 | 0 |

以上是固定樣本的欄位抽取與核對結果。畫質對辨識的影響另用 11 頁影像樣張記錄，涵蓋繁中、低對比與淺藍底。Chrome 實際 OCR 未產生可驗證的文字，因此沒有 Chrome 時間或跨引擎準確率比較。

## 11 頁本機 Tesseract 實測

1440 × 900 桌面測試中，由開始加入合成 PDF 到顯示檔案結果共 **15.606 秒**。逐頁時間由各頁進度出現到下一頁進度或檔案結果，包含該頁所需的影像處理。該次各頁耗時為 `2276、1586、514、1620、1413、1341、429、1300、1426、1882、588 ms`。

與樣張逐頁比對辨識出的文字，姓名精確命中 4／11、遮罩證號 0／11、道路／巷／門牌段 8／11、金額 8／11。頁面完成處理只代表有執行辨識。掃描遮罩證號與低畫質姓名仍須查看原件，必要時用逐頁貼入或人工確認。上述門牌段命中不涵蓋完整縣市區里鄰。

## 重現方式與畫面

執行 `npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`。Playwright HTML 報告在 `playwright-report/index.html`。手機、平板 (直式／橫式) 及桌面截圖由 `test-results/` 下的 `v4-chrome-paste.png` 和 `v4-chrome-results.png` 提供。品牌素材沿用 `src/ui/legaleye-icon.svg`、`public/icons/` 及 `brand/legaleye/`，並由既有品牌與響應式測試驗證。

代表截圖包括 [手機 390 × 844 貼入](screenshots/v4-390x844-paste.png)、[平板 820 × 1180 核對](screenshots/v4-820x1180-review.png) 與 [桌面 1440 × 900 貼入](screenshots/v4-1440x900-paste.png)。桌面效能測試附有合成 PDF 及計時 JSON，可用同一樣張驗證公司 Chrome。

手動真機、公司管理 Chrome／DLP、首次模型下載及 PAD 操作需另外驗證。開啟 Chrome 功能有疑問時，使用者可照 [掃描文件核對手冊](ocr-user-guide-zh-TW.md) 以法眼本機讀取或人工確認原件。
