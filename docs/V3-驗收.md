# 法眼 LegalEye V3 變更與驗收

改版前還原點為提交 `225dc7a`。現有首頁、四類核對、專利主檔、規則設定、使用說明及本機啟動方式沿用原有路徑。專利資料、設定識別碼和舊版 8 欄 CSV 讀取方式相容。V2 的深藍、灰白與字體配置保留。標誌仍使用 `src/ui/legaleye-icon.svg`，套用於首頁、側欄、頂欄、favicon 和 HTML 報告，公開圖示及單色素材位於 `public/icons/` 和 `brand/legaleye/`。

## 修改位置

| 範圍 | 檔案 | 變更 |
|---|---|---|

## 固定合成樣本對照

執行 `node tests/benchmark/v3-address.mjs`。腳本從 Git 的 `225dc7a` 讀取 V2 的實作，用相同輸入執行兩個版本。掃描疑點使用合成的辨識文字與頁面來源標記，影像辨識由 Playwright 另測。

| 指標 | V2 | V3 |
|---|---:|---:|
| 姓名欄正確 | 2／3 | 3／3 |
| 地址在預期分類 | 3／6 | 6／6 |
| 寫法相同或掃描疑點被報成內容不同 | 3 | 0 |
| 實際不同的巷號或樓層被抓到 | 2 | 2 |
| 掃描疑點留給人工確認 | 0 | 1 |

這些數字適用於上述固定合成樣本。請在公司核准環境用實際文件覆核不同戶謄版面及掃描品質。

## 待擴充及人工覆核範圍

- 局部裁切依已找到的唯一文字行定位。找不到唯一區域時可看原頁或重讀整頁。掃描旋轉以 PDF 的頁面方向及辨識引擎為基礎，任意角度影像校正與欄位字元精度仍待驗證。
- 同一書狀段落引用多件案號而無法區分各案金額或書狀起息日時，須人工覆核。多第三人或無法取得可供配對的第三人來源也會保留人工確認。
- 流程 B 可更正書狀案號及可開啟來源的身分欄位。流程 C 可更正所選戶籍人物的姓名、身分證與地址。流程 A、D 使用原有原件查看與覆核。
- 下載主報告為可列印或另存 PDF 的 HTML，其他格式提供 CSV。

## 建置與部署

在專案目錄執行 `npm ci` 和 `npm run build`。Windows 本機使用 `啟動法眼.bat`。GitHub Pages 使用既有 `.github/workflows/pages.yml`，在 GitHub 設定的發布來源選 GitHub Actions，再將變更推送至 `main`。流程只發布 `dist/`，其中含離線掃描辨識及 PDF 字型資源。

驗證指令為 `npm test`、`npm run test:e2e` 及上面的固定樣本腳本。Playwright 報告在 `playwright-report/index.html`，桌機、平板及手機截圖由 `test-results/` 各專案目錄產生。
