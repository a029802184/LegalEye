# 法眼 LegalEye 技術維護手冊

對象：日後負責更新、部署法眼的同事或公司 IT。一般操作請看《使用手冊》。

## 1. 架構概要

- React 18＋TypeScript＋Vite 5，純前端靜態網站，無後端、無資料庫、無登入。
- 主要相依：`jszip`（ZIP／DOCX／XLSX 容器）、`pdfjs-dist`（PDF 文字層與渲染）、`tesseract.js`（本機 OCR）。
  XLSX 讀寫、DOCX 解析、SHA-256、ZIP 安全檢查皆為專案內自行實作，無大型試算表套件。
- 所有第三方程式在建置時打包；OCR 語言檔、PDF.js CMap 由 `npm install` 自動複製到 `public/`，執行時**不連任何 CDN**。
- 正式建置會注入 Content-Security-Policy（只允許本站資源），見 `vite.config.ts`。

## 2. 開發環境

1. 安裝 Node.js 18 LTS 以上（實測 18.16）。
2. `npm install`（postinstall 會執行 `scripts/copy-ocr-assets.mjs`，產生 `public/ocr/` 與 `public/pdfjs/`）。
3. `npm run dev` 開發；`npm test` 單元測試；`npm run build` 建置；`npm run test:e2e` 響應式測試（使用本機 Microsoft Edge）。

## 3. 部署方式（擇一）

| 方式 | 步驟 | 適用 |
|---|---|---|
| 公司內網靜態網站（建議） | 將 `dist/` 整個資料夾複製到 IIS／Nginx 網站目錄，任意子路徑皆可 | 多人共用 |
| 單機啟動 | 把 `dist/`、`scripts/serve.ps1`、`啟動法眼.bat` 放在同一層結構，雙擊 `啟動法眼.bat` | 無 IT 支援時 |

伺服器 MIME 設定需包含：`.mjs → text/javascript`、`.wasm → application/wasm`、`.webmanifest → application/manifest+json`，
並讓 `.gz`、`.bcmap` 以二進位傳送（**不要**加 `Content-Encoding: gzip`，OCR 會自行解壓）。

不可直接雙擊 `dist/index.html`：瀏覽器在 `file://` 下禁止 ES 模組與 Web Worker。

若以 http（非 https）在內網部署：功能正常（雜湊使用自行實作的 SHA-256，不依賴 `crypto.subtle`），
但瀏覽器「分享」功能可能無法使用，改用下載即可。

## 4. 版本更新

1. 修改程式後執行 `npm test`、`npm run build`、`npm run test:e2e`，全部通過再部署。
2. 用新的 `dist/` 整個取代舊的。使用者端無需任何操作（不保存文件資料，無資料遷移）。
3. 更新 `package.json` 的 `version` 與 `CHANGELOG.md`。若核對規則行為改變，同步修改：
   - `src/core/rules.ts` 的 `RULESET_VERSION`
   - `src/core/service.ts` 的 `SERVICE_RULE_VERSION`（送達／利息規則）
   報告會記錄規則版本，方便日後追溯。

## 5. 資料與遷移

| 資料 | 存放 | 備份方式 |
|---|---|---|
| 專利案件 | 使用者匯出的 Excel 主檔（正式）；若使用者勾選，另暫存於瀏覽器 localStorage `legaleye.patents.v1` | 匯出 Excel 存共用資料夾 |
| 專利狀態設定 | localStorage `legaleye.patent.statuses.v1`，也寫入 Excel「案件狀態設定」工作表 | 隨 Excel 主檔 |
| 核對規則設定 | localStorage `legaleye.settings.v1` | 「規則與設定 → 匯出設定（JSON）」 |
| 上傳的法律文件 | 只在記憶體，不保存 | 不需備份；報告另行下載 |

- Excel 格式版本記錄在「資料格式版本」工作表（目前 2.0）。匯入依欄位**名稱**對應，欄位順序可變。
- 舊版 LegalDesk 概念驗證版 CSV（`內部編號、案件名稱、專利類型、申請案號、內部進度、下次確認日、承辦人、備註`）可直接匯入；
  欄位對照在 `src/patent/model.ts` 的 `legacy` 屬性。舊狀態值保留原文，不自動改寫。
- 設定 JSON 匯入時經 `migrateSettings()` 驗證，不合法欄位以預設值補上；若日後變更設定結構，請在此函式加上轉換並提高 `SETTINGS_SCHEMA`。

## 6. 規則維護（不需改程式）

「規則與設定」頁可維護：檢查項目停用（需填原因）、附件同義詞、法院簡稱、公司帳號主檔、Excel 債務欄位名稱、專利狀態。
需要新增「新的檢查邏輯」時才需修改程式：

| 要改的事 | 檔案 |
|---|---|
| 金額性質關鍵字（本金、已繳、本期應繳…） | `src/core/amount.ts` `KIND_KEYWORDS` |
| 文件角色判斷（依內容） | `src/core/classify.ts` `RULES` |
| 姓名、地址、編號抽取 | `src/core/extract.ts` |
| 送達／利息規則 | `src/core/service.ts`（附單元測試 `tests/unit/service.test.ts`） |
| 各流程比對 | `src/flows/flowA.ts`～`flowD.ts` |
| 新增檢查項目 | `src/core/rules.ts` `CHECK_CATALOG`，並在流程中以 `item(ctx, '<id>', …)` 產生結果 |

修改後請新增對應的合成資料測試（`tests/fixtures/datasets.ts`、`tests/unit/flows.test.ts`）。

## 7. 安全設計與限制

- ZIP：自行讀取中央目錄檢查項目數、宣告大小、壓縮比、加密、ZIP64、路徑穿越、重複路徑；解壓以串流方式，實際位元組超過上限即中止。
  上限設定在 `src/core/zip.ts` `DEFAULT_ZIP_LIMITS`。
- XSS：介面以 React 輸出（自動跳脫）；HTML 報告所有內容經 `escapeHtml`。CSV 匯出對 `= + - @ Tab CR` 開頭加單引號防公式注入。
- 個資：Console 不輸出文件內容；報告預設遮罩身分證、帳號、電話。
- **限制**：無登入、無權限控管、無中心化稽核；不能宣稱符合企業資安規範。正式上線前須由資安與法務確認部署、存取、留存與備份方式。

## 8. Logo 與品牌素材

- 主檔：`public/icons/legaleye-icon.svg`（圓角方形內的友善小眼睛；深藍 #243E59、白、霧藍 #7FB0D8）。
- 修改 SVG 後執行 `npm run icons` 重新產生 32/64/180/192/512 PNG 與 `favicon.ico`，並同步到 `brand/legaleye/`。
- 套用位置：桌面側欄（32px）、手機／平板頂欄（26px）、瀏覽器分頁（favicon）、PWA 圖示（manifest）、HTML 報告頁首（28px 內嵌 SVG）。
- 舊版圖示保存在 `brand/reference_old_logo/`，僅供參考。

## 9. 還原點

`legacy/LegalDesk_概念驗證版/` 保存升級前的原始 `index.html` 與說明；`legacy/LegalDesk_概念驗證版_原始壓縮檔.zip` 為原始壓縮檔。
需要回到舊版時直接以瀏覽器開啟該 `index.html` 即可（舊版為單一檔案，可雙擊開啟）。
